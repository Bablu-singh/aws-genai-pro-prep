Exam AIP-C01 · Professional tier

You have one month. Here is exactly how to spend it.

This is a professional-level exam about shipping generative AI on AWS — not about training models. Every question is a scenario with several technically workable answers, and your job is to pick the one that best fits the stated constraint: cost, latency, compliance, blast radius, or operational overhead. Where the marks actually are

Official weightings

Domains 1 and 2 are 57% of the exam between them. If your time collapses, protect RAG design, vector stores, prompt/agent architecture, and Bedrock API integration above everything else. Domain 4 and 5 are only 23% combined — but they are cheap to learn, because they are mostly CloudWatch, evaluation vocabulary, and a fixed list of failure modes.

The six habits that pass this exam

Strategy

1. Find the constraint word

Every stem hides one qualifier: least operational overhead, lowest cost, lowest latency, most secure, fastest to implement, minimal code changes. Two answers are usually both correct engineering; only one wins on the qualifier. Underline it mentally before reading options.

2. Prefer managed over assembled

When the qualifier is operational overhead or time-to-value, the answer trends to the managed primitive: Bedrock Knowledge Bases over a hand-built ingestion pipeline, Guardrails over a custom classifier, AgentCore Memory over DynamoDB session tables. When the qualifier is control, custom fit, or an unusual requirement, it flips.

3. Know what each service cannot do

Distractors are built from capability boundaries: API Gateway REST cannot stream tokens; a custom Bedrock model cannot be called on-demand; Guardrails do not read your knowledge base unless you wire grounding; Kendra is not a vector database you control. Learn the edges, not the marketing.

4. Build it once, in your own account

You have an AWS account — use it. Doing the twelve labs in this site once beats re-reading notes three times, because the exam asks about the parameter you had to set, the permission you had to grant, and the error you had to fix.

5. Drill under the clock

Professional stems are long. The failure mode is not ignorance, it is running out of minutes and rushing the last fifteen questions. Practise at 2 minutes per question, flag and move on, and never re-read a stem more than twice.

6. Multi-response is all-or-nothing

“Select TWO” gives no partial credit. Treat each option as an independent true/false statement against the scenario, choose the exact number asked, and resist picking two options that solve the same half of the problem — correct pairs usually cover two different halves.

Guard your AWS bill before day 1

Your account
Do this first Bedrock is pay-per-token and mostly outside the free tier. Two things will hurt you if you are careless: Provisioned Throughput (billed by the hour whether you call it or not, with 1- and 6-month commitment options) and OpenSearch Serverless collections (billed per OCU-hour with a minimum capacity floor, so an idle vector collection still costs money every day). What this exam is not

Scope discipline

The exam guide explicitly puts these out of scope for the target candidate: model development and training, advanced ML techniques, and data/feature engineering. So do not spend your month on transformer internals, backprop, hyperparameter tuning, or SageMaker training jobs. You need to know fine-tuning vs. continued pre-training vs. distillation vs. RAG as deployment choices — when to pick each and what each costs you operationally — not how to implement them from scratch.

Read the scope line twice A recurring distractor pattern: an option that proposes fine-tuning or training a custom model when the scenario only needs retrieval, a better prompt, or a guardrail. Fine-tuning is almost never the “least operational overhead” or “fastest” answer, and it does not fix factual freshness — retrieval does.

1 · How do I make the model know my data?

The customization ladder

Walk down this ladder and stop at the first rung that solves the problem. Almost every exam scenario stops at rung 1, 2 or 3.

RungTechniqueUse whenCost / overheadDiscriminator
1Prompt engineering, few-shot, structured outputBehaviour, tone, format, simple reasoning gapsNear zeroAlways try first. “Fastest to implement” and “no infrastructure” point here.
2RAG (Knowledge Bases + vector store)Model lacks facts: private docs, fresh data, citations requiredLow; embedding + storage costsAnything with “up-to-date”, “internal documents”, “must cite sources”, “reduce hallucination”.
3Agents + tools (function calling, MCP)Model must act: query an API, run code, do multi-step workLow–medium“Take actions”, “look up live inventory”, “multi-step task”.
4Fine-tuning (labeled prompt/response pairs)Consistent domain style, format, or task the prompt cannot reachHigh: training job + Provisioned Throughput to serveOnly when the scenario says prompting was tried and failed, or demands a specific proprietary style at scale.
5Continued pre-training (unlabeled domain corpus)Whole new vocabulary/domain (legal, biomed, internal jargon)HighestUnlabeled data + “domain knowledge” language. Rare on the exam.
6Model DistillationYou want a big model’s quality at a small model’s price/latencyMedium, one-off“Same accuracy, lower inference cost/latency, high volume.”
7Custom Model Import / SageMaker hostingYou own open-weight or externally trained weightsMedium–high“We already fine-tuned Llama on-premises and want it behind the Bedrock API.”
The classic trap Fine-tuning is offered as a distractor whenever the real problem is freshness or factual grounding. A fine-tuned model still does not know yesterday’s price list. Freshness → RAG. Style/format → fine-tune. Also remember: a fine-tuned Bedrock model cannot be invoked on-demand — you must buy Provisioned Throughput, which changes the cost answer completely.

3 · Which chunking strategy?

Task 1.5.1
StrategyBest forTrade-off
Fixed-size + overlapUniform prose; the safe defaultSplits mid-idea; overlap costs storage and duplicates hits.
Hierarchical (parent–child)Long structured docs: you retrieve precise small chunks but hand the model the larger parent for contextBest precision/context balance; more storage. Strong answer when the complaint is “answers lack surrounding context”.
SemanticMixed-topic documents where boundaries matter more than sizeCosts embeddings at ingest time; slower ingestion.
No chunkingEach file is already one atomic idea (FAQ row, product record)Blows the context window if files are large.
Custom Lambda transformCode, tables, transcripts, or a bespoke parserYou own it forever. Only when built-ins genuinely cannot express the rule.
Symptom → fix Retrieval returns the right document but the answer is incomplete → chunks too small / no parent context → hierarchical chunking or larger chunks. Retrieval returns loosely related junk → chunks too large (diluted embedding) → smaller chunks, or add hybrid search and reranking. Retrieval misses exact product codes or names → pure vector search → add keyword/hybrid search.

5 · Inference mode and pricing

Task 2.2, 4.1
ModePick it whenKey fact
On-demandSpiky, interactive traffic; unknown volumePay per input/output token, no commitment. Subject to account-level throttling.
Batch inferenceBulk, non-interactive jobs: nightly summarisation, backfills, evaluation setsRoughly 50% of on-demand price, results delivered to S3, higher and variable latency.
Provisioned ThroughputPredictable high volume, guaranteed throughput, or serving a fine-tuned modelBilled per model unit per hour; 1-month/6-month commitments cut the rate but cannot be cancelled. Required for fine-tuned/CPT models.
Cross-Region inference profileThrottling under bursts; a model with limited regional availabilityRoutes to other Regions in the same geography for extra burst capacity. Check data-residency wording before choosing it.

Latency-optimized inferenceInteractive UX where p95 latency is the requirementSet the latency performance configuration; limited to specific models and Regions.
Prompt cachingA long, unchanging prefix (system prompt, policy doc, few-shot block) repeated across callsCache the static prefix; large cost and latency reduction on cache hits, short TTL. Put the variable part last.
Intelligent prompt routingMixed query difficulty; you want cheap models to take the easy trafficRoutes within a model family based on predicted quality, one endpoint, no app changes.
Cost-reduction pecking order When a question asks to cut Bedrock spend with minimal disruption, the usual ranked answers are: 1) right-size the model (Nova Micro/Lite, Haiku) for the easy tier, 2) prompt caching for repeated prefixes, 3) semantic/response caching to skip invocations entirely, 4) shorter prompts and capped maxTokens, 5) batch for non-interactive work, 6) Provisioned Throughput only once volume is high and steady.

6 · How do I stream tokens to a browser?

Task 2.4.2 — a favourite
PathStreams?Notes
API Gateway REST / HTTP API → LambdaNoThe response is buffered and returned whole. This is the wrong answer whenever the requirement says “show text as it is generated”.
API Gateway WebSocket APIYesBackend pushes each chunk over the socket. Good for chat with bidirectional needs and long sessions.

On the model side the call is ConverseStream (or InvokeModelWithResponseStream). Converse/ConverseStream is the unified API: same request shape across models, native tool use, guardrail integration, and system prompts — prefer it over raw InvokeModel when the scenario wants model portability with no code changes.

Task 2.1, 2.5

Agent vs. workflow If the steps are known in advance and must always happen in the same order — use a workflow (Step Functions). If the steps depend on the input and the model must decide — use an agent. Exam scenarios that stress auditability, compliance, guaranteed retries, or “must never skip a step” want the workflow, even in a GenAI question.

9 · Evaluation: which tool answers which question?

Domain 5
Question you are answeringMethod
Which of these models is best for my task, on my data?Bedrock model evaluation — automatic (built-in metrics/datasets) for a fast first cut.
Is the tone, helpfulness, and brand fit acceptable?Human evaluation job (your own workforce or AWS-managed).
Can I score thousands of outputs on subjective quality without humans?LLM-as-a-judge — cheap, scalable, and the standard answer for continuous evaluation.
Is my RAG pipeline retrieving the right context and staying faithful to it?Knowledge Base / RAG evaluation — retrieval-only mode isolates retrieval quality from generation quality.
Did the agent complete the task and use its tools correctly?Agent evaluation — task completion rate, tool-selection accuracy, reasoning-step quality.
Did the new prompt/model version make things worse?Regression testing against a golden dataset in CI, with a quality gate before deploy.
Which of two live variants performs better with real users?A/B or canary with business metrics; shift traffic gradually.
Is the classic ML model drifting?SageMaker Model Monitor; SageMaker Clarify for bias and feature attribution.

Vocabulary you must not mix up: faithfulness/groundedness = the answer is supported by retrieved context. Answer relevance = the answer addresses the question. Context precision/recall = the retriever fetched the right chunks and not junk. A drop in faithfulness is a generation problem; a drop in context recall is a retrieval problem. That distinction decides several Domain 5 questions.

Sampling parameters — what each actually does

Task 4.2.4
ParameterEffectExam framing
TemperatureFlattens or sharpens the probability distributionDeterministic extraction, SQL, JSON, classification → near 0. Creative copy → higher.
Top-p (nucleus)Samples from the smallest set of tokens whose cumulative probability reaches pLower p → safer, more focused. Tune temperature or top-p, not both hard.
Top-kSamples only from the k most likely tokensBlunter instrument than top-p.
maxTokensCaps output lengthA direct cost control, and the fix for runaway generations.
Stop sequencesEnds generation at a markerStops the model rambling past the structure you asked for.
Inconsistent JSON output If a scenario reports the model returning valid answers but inconsistent formatting, the ranked fixes are: 1) temperature to 0, 2) enforce a schema (tool use / structured output / JSON Schema), 3) validate and repair in a Lambda post-processor, 4) add stop sequences and few-shot examples. Fine-tuning is the distractor.
